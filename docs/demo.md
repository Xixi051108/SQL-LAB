# 演示与实验报告素材

## 建议演示顺序

1. 以工号 T2026001 登录，确认显示陈明；在“师生名册”展示模拟教师和学生、录入一名待注册学生。随后展示教学概览、七类题型、教学库关系及环境状态。
2. 题库中新建查询题，演示 DeepSeek 生成草稿；说明 AI 输出不是最终标准，教师需核对题意。
3. 保存草稿，执行“验证审核”；修改题干或 SQL 后状态恢复草稿，再次审核。
4. 删除刚创建的测试题，展示题库新增、修改、删除和持久化。
5. 创建考试，选择七类已审核样题，设置分值总计 100 分、开始时间为当前或稍早、结束时间为数分钟后，保存并发布。
6. 退出教师账号，使用名册中的学号与姓名注册新学生，进入后显示姓名。退出后用学号与密码再次登录，进入考试。输入查询答案，切题，刷新后展示答案保留与保存提示。
7. 建表题填写包含主键和外键的正确 SQL；其他题可故意错写一题。
8. 提前交卷，展示总分、逐题反馈和参考解析；强调 SQL 效果相同可以通过，不要求字符串相同。
9. 返回考试，展示只能看结果，不能重新答题。以教师查看成绩记录。
10. 可另开一场短时考试演示截止交卷；先保存答案，再等待截止。不要直接修改电脑时间。

所有题目使用独立初始数据，不需要在上一题创建表后才能作答下一题。

## 报告可用结构

### 实验目的

掌握需求分析、数据字典、E-R 建模、关系模式转换、数据库完整性设计及 Web 应用开发。结合大模型辅助出题和真实 SQL 执行，构建从教师审核到学生考试和评分的业务流程。

### 实现内容

系统包含教师与学生角色、题库管理、DeepSeek 出题、执行审核、限时组卷考试、自动保存、判题队列及结果查询。七类核心实体（含师生名册）通过外键建立联系，唯一约束控制重复作答和重复答案。已发布试卷保存题目快照，以保证历史成绩可解释。

### 关键设计说明

SQL 查询题比较结果，数据修改题比较最终数据，表结构题比较字段和约束。每次执行重建练习库，解决 DDL 无法仅靠事务回滚的问题。判题账号无法访问业务库，模型调用不进入考试评分的关键路径。

### 测试与结果

引用 `docs/tests.md` 中实际执行的命令、用例及结果；将自己演示时的页面截图补充到报告中。不要把模拟故障测试写成真实线上故障，不要把两组数据验证描述为任意 SQL 等价性的证明。

### 结果与改进方向

第一版适用于单机课堂演示，覆盖七类常见 SQL 的考试闭环。限制为固定教学库、单条课程 SQL 和单进程串行判题。后续若要面向不可信公众提供服务，需进一步隔离数据库实例、限制计算资源并扩展题目测试数据和人工审核流程。
